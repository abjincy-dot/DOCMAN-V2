## Project Context

DOCMAN is a native Android document manager app (Capacitor-wrapped web app).
Package: `com.docman` (renamed from `com.oarcel.docman` on 2026-09-12, before first publish; `applicationId` in android/app/build.gradle).

## Architecture
- **Web layer**: `www/app.js`, `www/index.html`, `www/style.css` — main UI/logic, single-page app style.
- **Native layer**: `android/app/src/main/java/com/docman/`
  - `MainActivity.java` — Capacitor bridge entry point, registers plugins.
  - `PdfViewerActivity.java` — native PDF viewer (AndroidPdfViewer/PdfiumAndroid + PDFBox for text extraction). This is where PDF feature work happens.
  - `PdfNativePlugin.java` — Capacitor plugin bridging JS ↔ PdfViewerActivity (open PDF, Continue Reading page tracking).
  - `PdfMarkOverlayView.java` — screen-space circle-mark overlay for screenshots (not persisted to PDF).
  - `BiometricAuthPlugin.java` — fingerprint/face unlock.
  - `DocmanWebChromeClient.java` — handles the WebView's file picker (Camera/Photo Library/Choose Files/Google Drive).

## Current PDF Viewer status
Native viewer (PdfViewerActivity) has: Bookmarks (TOC + user page-bookmarks), Text Search (page-level, via PDFBox), Rotate, Night Mode, Horizontal/Vertical scroll toggle, Two-Page/Spread view, Fullscreen, Page Thumbnails grid, Continue Reading (last page memory), Zoom/pan (pinch), Screenshot-mark overlay, Print (Android PrintManager), Security (password-protected PDF unlock via `.password()` + `onError` detection), Export (save copy to Downloads via MediaStore), Copy Page Text, drag-to-select Text Selection + Copy (`PdfTextSelectionOverlayView.java`, per-page lazy PDFBox extraction), Attachments (document-level + per-page FileAttachment), Highlight annotations (real `PDAnnotationTextMarkup`, on-screen immediately + saved on exit if kept), Signature (draw in black or ballpoint-blue ink, remembered in viewer prefs + drag/pinch-resize placement, `PdfSignaturePlacementView.java`, stamped as an image), Fill Form (list-based: every text field/checkbox in the AcroForm, saved via `PDField.setValue()`), Erase (`PdfRedactOverlayView.java` — a brush: one finger paints strokes on any page, a second finger hands the gesture to PDFView to move/zoom; each piece of a stroke is filled with the paper colour sampled around it (from a small page render, so the screen shows the saved result) or black; every affected page is flattened to a raster image so the content is genuinely removed, saved once as `_erased.pdf`/`_redacted.pdf`; rotated pages are skipped rather than risk misplacement), Crop Page (`PdfCropOverlayView.java` — drag one rectangle on the current page, then shrinks that page's own MediaBox/CropBox to the marked area (Acrobat's "Crop Pages" model: no content-stream rewrite, so it's near-instant unlike Redact's rasterize step); same rotated-page refusal as Redact, since the screen-fraction→PDF-point conversion assumes unrotated correspondence). All of these (Highlight/Signature/Fill Form/Erase/Crop Page) save a new copy next to the original, in the same DOCMAN folder, never overwriting it. `saveEditedCopy()` writes a verified PDF plus a `{name, docId}` JSON note to `cache/edited/`. `importPendingEditedCopies()` in `www/app.js` then files it with a native `Filesystem.copy`, on the viewer's `editedCopySaved` event, on resume, and at launch. A document with no docId falls back to Downloads. Export (More menu) and attachments still save to Downloads on purpose.

## Roadmap
All items from the original roadmap (Copy Page Text → Redaction) have shipped. No open PDF-viewer feature work queued.

- **OCR fallback (scanned/image-only pages)**: `com.google.mlkit:text-recognition:16.0.1`, on-device Latin recognizer, no network/API key. Triggers in both text-extraction paths whenever PDFBox's `PDFTextStripper` finds zero text objects on a page: `ensurePageTextLayoutForPage()` → `runOcrFallback()` (feeds Text Selection/Highlight, word-level `CharBox` with `wholeUnit=true`) and `ensurePageTextsExtracted()` → `ocrPageTextFallback()` (feeds Search and Copy Page Text, plain string via `Text.getText()`). Renders the page to a bitmap via a fresh `PdfiumCore` open (`renderPageBitmapForFlatten()`) at ~2.5px/pt, then runs ML Kit against it. Works well on printed/typed scans (photocopies, faxed forms, receipts) — the original target. Confirmed via on-device testing that cursive handwriting is recognized too poorly for reliable exact-word search (ML Kit's Latin recognizer is built for print, not handwriting); this is an OCR-model limitation, not a wiring bug.

## Decided against
- **EmbedPDF** (JS/WASM PDF.js-based viewer) was trialed as an alternative rendering engine but had unresolved reliability issues on this WebView: `worker:true` hung indefinitely on "Loading document…" (Module Worker + dynamic import() limitation, unconfirmed root cause); `worker:false` loaded reliably but showed blank tiles during fast scroll on large documents (main-thread rendering couldn't keep pace). Decision: stick with the native PdfiumAndroid engine and build features natively in Java. EmbedPDF's UI couldn't be reused with the native engine either — tightly coupled to its own WASM engine's internal APIs, no clean swap point existed. **Fully removed from the codebase** (JS wiring in `www/app.js`, DOM/CSS in `www/index.html`/`www/style.css`, the Settings "Viewer Engine" toggle, and the `www/vendor/embedpdf/` vendor files) — this was a real trial, not a currently-available option.

## Working style notes
- Native code changes should be defensive where a library's exact API surface can't be verified offline (e.g. `PdfPasswordException` detection uses a runtime class-name/message check rather than a hard import, since the exact package path varies across AndroidPdfViewer/pdfium-android versions).
- When extending `PdfViewerActivity`'s "More" menu, follow the existing pattern: add to the `items` array in `showMoreMenu()`, add a corresponding `case N:` in the switch, keep new methods consistent with the existing ones' structure (Toast on failure, no crashes on missing data).
- Never use `innerHTML +=` on `#content` (or any container the app has already wired up): it re-parses everything already inside and silently drops every listener attached to those nodes. This killed the folder toolbar's Favourite button whenever a folder had no notes (2026-09-16). Use `insertAdjacentHTML("beforeend", ...)` or `appendChild`, and prefer inline `onclick` for the toolbar buttons, which survives a re-parse.
- **`env(safe-area-inset-bottom)` is 0 in this WebView** — targetSdk 35+ draws edge-to-edge and never publishes the inset, so anything that trusts it sits under the gesture/back bar. The app's own measurement is `--nav-bottom`, written onto the root by `MainActivity` from the real window insets. Always reserve `max(env(safe-area-inset-bottom, 0px), var(--nav-bottom, 0px))` — the `max()` covers both a phone that does publish the inset and one that does not. Bit the note editor on 2026-10-13 the moment its card was made full height, and the reminder sticky note the same night. **JS has the same trap:** `innerHeight` runs to the bottom of the screen, so anything deciding whether something fits must use `innerHeight - Math.max(--safe-bottom, --nav-bottom)`, as the row menu and `showReminderStickyNote` now do.
- **`showModal` falls back to the OK button's label for the heading** (`const dlgTitle = title || resolvedOkLabel`). A `showConfirmModal` caller that passes no `title` gets a heading like "View" or "Delete", which reads as a stray verb rather than a title. Always pass `title`.
- **Scroll versus gesture on the PDF view**: `PdfTextSelectionOverlayView` decides whether a touch is a scroll by asking whether the PAGE moved (`pdfView.getCurrentXOffset()/getCurrentYOffset()` against the values taken at ACTION_DOWN), not by how far the finger travelled. Finger distance cannot tell a slow deliberate scroll from a hold, and the long-press slop there is deliberately generous to survive hand tremor. Reuse the page-offset test for any new gesture that has to coexist with scrolling.
- **The note editor opens for READING.** Both fields are `readOnly` until asked otherwise: the writing box needs a double tap, the one-line title a single one. Colour, ruling and text size are saved on the spot by `noteStyleChanged()` and never leave read mode, so no Save/Cancel appears while reading. Anything new added to that editor has to decide which of those two it is, or it will open a keyboard over a note somebody is only reading.
- **A launch that came from tapping a notification skips the launch dialogs** (`launchedFromNotification` guards `checkLaunchAlertsOnLoad`; the separate `checkExpiryTodayOnLoad` and its red modal were deleted 16 Oct). The tap is already an answer to an alert and already chose a destination; a dialog on top of it is nagging. Any new launch-time popup needs the same guard.
- **One list, one rule (17 Oct).** "Needs your attention" (`showExpiryCardsPopup`, fed by `getAttentionSets()`, the only definition of what needs attention: documents 3 days away or closer, overdue ones, and due reminders) is a single list. An item stays until it is **Done** (`acknowledgeExpiry` / `dueAckFor`) or its date changes; looking at the list never hides it. Cards: wide Edit button, then Open | Done. Open on a document = `revealFileInFolder` (folder + flash), on a reminder = the note. Every notification, reminders included, opens this same list. The old summary/detail screens, the red/purple expiry box and the one-day "counted" store (`docman_attn_seen_v1`, `markAttnSeen*`) are gone from use; do not bring them back.
- **The header bell** (`updateAttentionBell`, `#appLogoBtn`) is armed only by the launch check (`attentionBellArmed` / `armLaunchBell`); adding a reminder or date mid-session must NOT make it ring. Animation: a tiny bell zooms in, rings, fades at its normal size (`naBellIn`, end of `style.css`). At zero items the box logo returns.
- **A search left alone for 10 s is cleared and the app returns to the home screen** (`SEARCH_IDLE_MS`, `searchIdleCheck`, next to `clearSearch`; also checked on return to the foreground). The user asked for it because a leftover search made files look missing.
- **After adding or editing a reminder the calendar must move to that reminder's date** (`remindersCalSelectedIso`), or the panel says "No reminders on this day" for a reminder that exists.
- **Never edit `www/` files with PowerShell `Set-Content` / `Out-File`.** It re-encodes UTF-8 as Windows-1252 and adds a BOM; 68 shipped with the whole help screen garbled that way. Use Node or the Edit tool, then check `grep -a -c "â€\|ðŸ" www/index.html` is 0 and the file does not start with `ef bb bf`. A build verified only by `node --check` or a build log proves nothing about encoding.
- **`npx cap sync android` copies everything in `www/`, including strays** (a `www.zip` was there on 17 Oct). After syncing, list `android/app/src/main/assets/public` and delete anything that is not app content before `bundleRelease`.
- **Version state (20 Oct):** Play has 68 (broken text, never promote), 69 on Internal testing. The file to upload is `DOCMAN Play Store Assets/release/DOCMAN-1.0.0-versioncode77-UPLOAD-THIS.aab` (75 is on Internal testing; 76 was never uploaded); if Play refuses 77 as used, build 78. The final public build must read versionName 1.0.0. Always tell the user the versionCode and wait for a yes before building. R8 release behaviour (Sign dialog, PDF tools) has never been run on a phone.
- **Look at the phone screen only when the user asks**, and say only what is needed: the screen can show private apps. Send previews as PNG images (an HTML page did not render on the user's screen).
- **Text, Word and Excel viewers** share one look (white card on grey, selectable text, find, "Open with another app" via `openExternallyNative`). `body{user-select:none}` is the reason text is not selectable by default — a new viewer must opt back in.
- **`adb exec-out screencap` returns a black image when the phone is locked or the screen is off.** Wake it or ask the user; do not conclude the app is blank.
- Node heredocs lose backslashes inside template literals (a regex `\/` became `/`). Write longer edit scripts to a file with the Write tool and run `node --check www/app.js` after every edit.
- **Android allows 500 alarms per app and the notification plugin crashes the whole app past that** (on its own thread, so a JS `try/catch` cannot stop it). Every alarm scheduler stays under `ALARM_BUDGET` (450) minus what is pending (`imgScheduleExpiryNotification`); a document arms up to ~25. Reminders have no such check yet.
- **"No bell, no banner" is almost always the one-day counted store** (`docman_attn_seen_v1`): opening a banner line or pressing a card button counts items for the day, and your own test taps do it too. Check it first (`getAttentionSets()` via devtools: `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`). Resetting it from outside only sticks if the app keeps running ~8 s before `force-stop`. Never `pm clear` (it wipes the user's data).
- **Zoom in the text, Word and Excel viewers is a pure scale** (`applyScaleZoom`, wrappers `#textZoomWrap/#wordZoomWrap/#sheetZoomWrap`), never font-size or CSS `zoom`: those re-lay out (a real 4.5 MB note took 0.6-0.9 s per step) and the point under the fingers does not stay put. `wirePinchZoom` previews with a transform, commits once on finger-lift, and ignores movement until every finger is up (the same rule the PDF viewer needed).
- **The Excel viewer draws the used area only, merged cells as colspan/rowspan, with the file's own column widths/heights** (`XLSX.read(..., {cellStyles:true})`). A sheet's declared range can be far larger than its data (858 x 274 for 41 rows).
- **Use the devtools bridge to measure instead of guessing** (`Runtime.evaluate` over `ws://localhost:9222/...`, Node 24 has a global `WebSocket`): element sizes, timings, localStorage, file/expiry state.

## Lessons from 19-20 Oct (read before touching the Reminders panel, the note, the Excel viewer or the logo)
- **The user clears the chat without warning.** Log every correction in `CURRENT_STATE.md` the moment it is made (what, file, version, how to revert). A cleared chat leaves nothing else.
- **Ask once, with options, when a design word is ambiguous** (which corner, which curve, which "line width"). Two wrong guesses on the Reminders button bar (a box on every card; then rounding the bar's corner) cost the user hours and an angry message. Never change a shape the user has approved on a guess.
- **Do not test with the user's real data.** A test script that wrote sample `details` into reminders on the phone cleared every reminder's real details afterwards. Test on a copy or in the Edge render (`xl/shotrem.js`, `shotnote.js` in the scratchpad pattern: load `www/index.html` in headless Edge over CDP, remove the onboarding overlay, inject sample `reminders`).
- **Measure gaps from a phone screenshot, not from CSS.** `getBoundingClientRect` lied about the arm-to-card gap (the `::after` pseudo-element is positioned differently); a pixel scan of `adb exec-out screencap` was right. Zoom in with sharp (`resize` + `lanczos3`) and compare side by side with the reference at the same scale.
- **Reminders / Expiring panel (`showExpiringDocumentsPanel`)**: ONE shared button bar (`xcSetupSharedRail`, sticky) with a thin line (`.xc-shared-rail::after`, width from `--xc-arm`) running out of its top and curving down at the right; each card is a separate navy pill (`.xc-body`) with a thin white border; the counts strip (`.xc-stats`) sits under the tab row; the panel starts 38 px from the top. Many late CSS blocks override earlier ones: add new blocks at the END of `style.css` and check the cascade (the 19 Oct deck/rail rules are still underneath). Reminders cards need `margin-right:7px`, Expiring `3.5px` to end at the same x.
- **`.stagger-rows` rise on the Expiring list was the jerk** when switching tabs (the bar and the cards rose out of step). It is switched off (`animation:none`). Reminders never had it. Measure per-frame positions through devtools before guessing at a cause.
- **The reminder note (`.rnote-sticky`)** is a yellow band (title inside, no "Reminder" word), a dotted perforation line, and white ruled paper: the ruling is a 24 px tile on `.rnote-main` with `background-attachment: local` so it scrolls with the text; the details must NOT have their own scroll box (a nested `max-height` box was why the lines stayed still). Source CSS is also in `preview/note-style.css`.
- **`showModal` options added:** `onDismiss` (X and tap-outside call it instead of the callback) and `xcFlow` (use the dark-orange `xc-flow` theme). The Add-reminder windows (title, details, date) must all look the same; the details window was purple because only `icon === 'fa-bell'` got the theme. `showDateModal` option `noPreselect` is used by expiry edits: no date is pre-selected and Save reads "Pick a date" until one is chosen.
- **Excel viewer** (`openExcelViewer`): `parseXlsxStyles` (JSZip, no new dependency) reads cell fills, fonts, borders and alignment; a sheet over 3000 cells is drawn as a window of rows AND columns (the real report has a 48 x 977 sheet) with spacer rows, so switching tabs takes 20-230 ms; find reads the data (`_vfind`). Sheet tabs are at the bottom. Do not go back to drawing every cell.
- **Header logo:** `Images/calendar-tray.png` is the user's calendar + tray picture (bigger tray, orange rim, no glow); the live weekday/date text is positioned with `cqh` units in `.lc-d` / `.lc-n`. Header gear = `Images/settings-gear-docman.png` (the old `settings-gear-3d.png` is untouched). If a picture is replaced, the text positions must be re-measured.
- **Install recipe on this PC:** `JAVA_HOME=C:/Program Files/Android/Android Studio/jbr`, `npx cap sync android`, `android/gradlew installDebug`; then `adb shell monkey -p com.docman.dev -c android.intent.category.LAUNCHER 1`; forward devtools with `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`. If a write fails with `UNKNOWN: unknown error, open ...`, it is a transient file lock: wait 3 s and retry. If `adb devices` is empty the cable/USB debugging is off: ask the user, do not keep retrying.
